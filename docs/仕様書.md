# Disk Ledger 仕様書

2026-11-14 時点の検討案。アプリ名は Disk Ledger（2026-11-14 決定）。

## 1. 目的と範囲

Mac の内蔵ディスクで何が容量を使っているかを、階層の図と一覧で見せる。CleanMyMac の Space Lens に近い機能を中心とし、メモリ解放、マルウェア検査、アプリの最適化のような機能は作らない。

消す操作は最小限にとどめ、ゴミ箱へ移すことだけを許す。完全削除はアプリからは行わない。

この Mac の現状（2026-11-14、df）は、データ領域が使用 276GB、約240万項目、ローカルスナップショットが2本ある。最初の版はこの規模を数十秒で読み切ることを目標にする。

## 2. 構成

- SwiftUI のウィンドウアプリ。解析部は SwiftPM のライブラリ LedgerCore に分け、Time Machine Viewer の TMCore と同じ形にする
- Swift 6、配置対象は macOS 26.0（GitHub Actions の macos-latest で動かすため。Comma Switcher で 27.0 にして CI が落ちた経緯がある）
- サンドボックスは使わない。ホーム以外やライブラリの奥を読むためで、App Store には出さない。署名は当面ローカル署名、Hardened Runtime は有効にしておき、後から Developer ID と公証を足せるようにする
- フルディスクアクセスがないと Mail、Safari、Messages、他アプリのコンテナなどが読めない。起動時に保護された場所を一つ試しに読み、読めなければ許可の手順を出す。許可がなくても読める範囲で動き、読めなかった場所は「読めない」として図に残す

## 3. 容量の数え方

ここが CleanMyMac 型アプリの正確さを左右するので、最初に決めておく。

| 項目 | 方針 |
|---|---|
| ファイルの大きさ | 論理サイズではなくディスク上の割り当てサイズ（totalFileAllocatedSize）で数える。疎なファイルや圧縮ファイルで差が出る |
| ハードリンク | inode 番号で一度だけ数える |
| APFS のクローン | 複製したファイルはブロックを共有しており、単純に足すと実際より大きくなる。getattrlistbulk の ATTR_CMNEXT_PRIVATESIZE で「消せば空く量」が取れる見込みなので、実機で確かめてから使う |
| iCloud の未ダウンロード | 中身がないファイルは 0 として数え、雲の印で区別する。走査がダウンロードを起こさないよう、中身は一切開かない。CloudStorage 配下は Time Machine の調査で走査が時間切れになった場所なので、既定では深く潜らず一覧だけ出す |
| ボリュームの境界 | 外部ディスクやネットワーク共有には入らない。/System/Volumes/Data の firmlink で同じものを二度数えない |
| パージ可能な領域 | volumeAvailableCapacityForImportantUsage と volumeAvailableCapacity の差を「macOS が必要に応じて空ける領域」として別に出す |
| ローカルスナップショット | tmutil listlocalsnapshots で本数を出す。スナップショットが残っている間は、ファイルをゴミ箱に入れて空にしても容量が戻らないことを、削除の前に知らせる |
| 説明のつかない分 | ボリュームの使用量から走査で数えた合計を引いた残りを「システムとその他」として一つの塊で出し、内訳があいまいなことを i ボタンで説明する |

## 4. 走査

- 列挙は FileManager の enumerator ではなく getattrlistbulk（または fts）で行う。一回の呼び出しでディレクトリ内の名前、種類、サイズ、inode をまとめて取れるため、数倍速い
- ホーム直下や /Applications などの上位のディレクトリごとに並列に走らせ、同時に動かす数は CPU の数程度に抑える
- 進み具合は、読んだ件数、読んだ容量、いま読んでいるパスで出す。途中でも読み終えた部分から図を描く
- 結果の木は、ノード一つを数十バイトの構造体にして配列で持ち、名前は一つの文字列領域にまとめる。300万件でも 100MB 程度に収める
- 走査結果を Application Support に保存し、次に開いたときはすぐ前回の図を出す。開いている間は FSEvents で変わったディレクトリだけを読み直す（第二段階）

## 5. 画面

ウィンドウを左右に分ける。

- 左は図。中心から外へ階層が広がる円形の図（サンバースト）を第一案とする。扇をクリックするとそのフォルダが中心になり、パンくずで戻れる。小さすぎる扇は「その他の小さな項目」にまとめる
- 右はいま中心にあるフォルダの中身の一覧で、名前、容量、割合の棒、最終使用日を大きい順に並べる。図と一覧はどちらで選んでも互いに強調される
- 上部にボリューム全体の帯を出し、使用中、パージ可能、空きの比率と、カテゴリ別の合計を色で示す
- 項目の右クリックで Finder に表示、クイックルック、パスのコピー、ゴミ箱に入れるを出す
- 見ればわかる説明は書かず、パージ可能領域やクローンのように誤解されやすい数字にだけ i ボタンの吹き出しを付ける
- 書体はシステム標準（SF と ヒラギノ）で、Arial は使わない

### 見た目の方針（2026-11-14、参考画像なし）

モダンでありつつ堅実で、信頼感のある見た目にする。容量の数字を正しく読ませることを飾りより優先する。

- 骨組みは macOS 標準の部品だけで組む。サイドバーは NavigationSplitView、一覧は Table、ツールバーとシートも標準のものを使い、Liquid Glass はシステムが付ける分だけにとどめ、独自のガラスや光の効果は足さない
- 色は無彩色の地に、操作と強調だけに使う一色（落ち着いた紺青）を置く。図のカテゴリ色は彩度を抑えた6〜8色に限り、色覚の違いでも隣どうしが見分けられる組み合わせにする。グラデーション、影の重ね、派手な警告色は使わない。赤はゴミ箱へ移す確認の画面だけに使う
- 数字は等幅の数字（monospacedDigit）で右にそろえ、単位は GB と MB を十進（1GB = 10億バイト）で Finder と合わせる。割合の棒は細く、角の丸みは小さくする
- 動きは控えめにし、図の中心を移すときの短い遷移だけにする。走査中は数字と進み具合の帯が静かに増える形にし、回るアイコンは使わない
- ライトとダークの両方に対応し、システムのアクセントカラーと文字の大きさの設定に従う

## 6. カテゴリと提案

場所の決まりに合うものに名前を付け、全体の帯と一覧で目立たせる。決まりは JSON の表で持ち、後から足せるようにする。この Mac で大きくなりやすいものを優先して入れる。

- 開発 Xcode の DerivedData、Archives、シミュレータのランタイムとデバイス、Homebrew のキャッシュ、各プロジェクトの node_modules、.venv、target、.build
- モデル LM Studio、Ollama のモデル置き場
- アプリのキャッシュ ~/Library/Caches、各アプリの Cache や Code Cache（Claude アプリ、Chrome など）、Claude の vm_bundles
- バックアップ iPhone のバックアップ（MobileSync）、Time Machine のローカルスナップショット
- 書類 ダウンロード、写真ライブラリ、メールの添付、ゴミ箱

「消してよいもの」を断定はせず、「再生成されるもの」「アプリが使っているもの」のように性質だけを表示する。一括で掃除するボタンは作らない。

## 7. 大きいファイルと古いファイル

別のタブで、指定したサイズ以上のファイルを大きい順に並べ、種類と最終使用日で絞り込めるようにする。最終使用日はアクセス時刻があてにならないので、Spotlight の kMDItemLastUsedDate を使い、取れないものは更新日で代える。

## 8. ゴミ箱へ移す操作

- FileManager.trashItem だけを使い、rm 相当の処理はコードに持たない
- /System、/Library の Apple 管理部分、アプリ本体の中身、ホームの直下のフォルダそのものは選べないようにする
- 確認の画面に、選んだ件数と、クローンやハードリンクを考慮した実際に空く見込みの量を出し、ローカルスナップショットがある場合はその旨を添える
- 移した記録をアプリ内に残し、そこから元に戻すを呼べるようにする
